This isolated draft is based on 0806abf9be7565f7c2c79766329ab2d38911fcf7.

## Publication authority

The existing explicitly selected `ascify-admitted-v1` projection gains inventory
for grid/coalesced values, binary/labeled factories and int plus/max reduction.
The physical headers, embedded bodies, manifest lengths/hashes and profile test
pins change together. A declaration in that inventory grants no operation by
itself. The whole current translation unit must pass `ProveDynamicWarpGroups`.
All SDK records/functions and all their redeclarations must belong to the
physically verified, unmodified projection in this CompilerInstance.

The source domain is ordinary C++17 CUDA with standard preprocessing,
`dav-c310-vec`, recipe `none`, and no AMAP. Product main selects the normal CUDA
host driver. The initial reviewed physical SDK is CUDA13.4, with the actual
LLVM23 host-driver tuple `aarch64-conda-linux-gnu;13.2;nvptx64-nvidia-cuda`.
No device observer is enabled and no foreign AST is consumed. Response files,
explicit driver configs and caller SDK-metadata flags cannot authorize this
feature. Existing physical original-CG lookup, seven registered providers,
compiler controls and EOF revalidation remain mandatory. Partitioning,
functional, reduction, coalesced-reduction and coalesced-scan provider bytes/UIDs
plus the private backend are
additional data witnesses. They never acquire AST or macro ownership merely
by being listed in an input ledger.

## Typed domain and exact witnesses

Group values are non-static, non-volatile direct local values in ordinary
non-template device/global functions. Grid values permit only ULL rank/size.
Coalesced values originate from the genuine no-argument factory, binary
partition of an earlier same-function coalesced value or genuine SDK tile32,
or int-labeled partition of an earlier coalesced value. Direct evaluated uses
are unsigned queries, int/uint broadcast from literal rank zero, int reduction
with an exact zero-argument owned plus/max functor, and another proved factory.
All value references, types, calls and observations are inventoried. Activation
and final refusal inventories cover every caller file, including unselected
retained headers. A foreign-only sizeof/type/alias/callee observation also
activates the closed gate; it cannot escape through an empty selected-source
use count. Only selected source values and calls may acquire local witnesses.
An unselected header must therefore be selected for the source closure or be
refused. Source function-template imports are chased to their actual typed
function declaration for the refusal inventory; no template gains admission. Copies,
references, addresses, assignments, escapes, aliases, sync and representation
inquiries remain refused. Builtin unevaluated contexts use real BuiltinInfo.

The new static-parent proof requires a genuine literal `tiled_partition<32>`
from a same-function local `this_thread_block` value. Only its genuine owned const SDK conversion method may adapt the concrete
tile32 type through the exact checked full-expression temporary chain. An
optional single same-type const PRValue qualification does not grant other casts. Every block
reference must be a genuine direct partition argument. Every tile reference
must be a genuine binary-partition or free-sync argument. This closes writes,
reassignment and foreign factory origins; it does not infer a barrier contract
from the class name. Only literal NTTP source expressions are accepted. Parent and CTA TypeSourceInfo
must be literal macro-free auto or the exact SDK record/template spelling,
with literal32 and void/SDK-block template arguments. Typedefs, decltype,
macros and unrelated templates cannot borrow canonical SDK type identity.
When a static parent is actually used, every caller block/tile32 TypeLoc,
including retained unselected headers, must belong to those exact proved
local declarations. Layout/alias/template/unevaluated observations outside
those ranges refuse, as do bare class-method lookups. This inventory has a
separate native-source callback and does not mistake native/profile templates
for caller observations. Inputs without dynamic use keep their prior domain.

Actual DeclRefExpr, MemberExpr and qualification leaf locations must be physical
caller tokens. A raw lexer checks every selected expression/type range for
clean tokens and active macros, including parenthesized callee aliases and
nested-name qualifiers. Only exact current-AST factory/value/ref/callee/functor
and TypeLoc nodes enter the generic record audit exceptions. The sole callee
decay wrapper is proved by cast kind and same function type. Traversal of all
children, inquiries, template arguments and concrete instances continues.
No body, SDK type, arbitrary SDK callee or implicit cast receives a bypass.
Caller declarations in owned namespaces or of register dependencies are refused
across the TU, including unselected retained caller headers. The newly exposed
`greater` family participates in activation/refusal even for dependent types,
standalone/foreign layout inquiries and direct operator calls. Only the exact
zero-argument `greater<int>` temporary inside a proved reduction can provide
its constructor and precise TypeLoc nodes. The shared older plus family keeps
its existing gates. A using-import of the already exposed reduce name, or its
unresolved lookup, does not alone activate the new domain; any actual new-group
observation still activates all final alias/lookup refusal checks. New factory
lookups in uninstantiated templates are inventoried and refused.

An actual unexpected macro expansion of a newly introduced class/factory name or its containing SDK namespace
inside the pinned profile is rejected before typed inventory. Otherwise a
macro could erase the canonical name and make an observed new type appear
unrelated. This check is tied to the real profile expansion, not merely a
same-name macro defined after the profile. The pinned profile namespace must
also remain at translation-unit scope, closing namespace wrapping as another
way to erase canonical group names. These are rejection-only topology/control
checks and confer no AST or macro role.

## Macro, backend and closure boundaries

The separate sorted identifier inventory covers every identifier token in the
unchanged a26e6f backend. New checking is conditional on an admitted dynamic
use. It retains all define/undef events, incoming/command-line states and raw
inactive define/undef or macro-stack history. Native ownership requires the
existing real SDK/compiler roles or unchanged physical native system inputs;
caller system-header markings do not confer that role. Private original
`_CG_*` and `_COOPERATIVE_GROUPS_*` controls receive the same complete scoped
history audit, closing newly registered SDK include guards without changing
the legacy global control list. All retained caller conditional directives
are conservatively refused in this first domain, including target-only
branches. Exact frozen official helper bytes have only a conditional-token
role; their macro/name checks and independent closure proof remain mandatory.
When a dynamic TU contains a recognized sample-helper include, output publication
also requires the existing current local-header context's actual helper transaction
to have committed after closure finalization. This gate does not set any helper
proof or permission flag. Inputs without a sample helper retain their ordinary
single-source domain; legacy inputs without dynamic observations retain prior gates.
The raw inventory alone also accepts physically owned compiler resources through
the existing full-warp native-parent proof: actual product resource directory,
UID and parsed bytes, a real initial native system ancestor and no caller command
macro token mention. This does not grant SDK AST or macro-provider ownership.
Only four exact observed compiler cacheline push directives may bypass the raw
macro-stack token refusal: two occurrences for each of the constructive and
destructive size names, in this CI's whole unchanged actual predefines buffer.
Caller push/pop directives and unrelated predefines tokens retain their gates.
Caller tokens naming the new owned namespace or register dependencies refuse
even in inactive code. Ordinary selected headers use pragma-once or no guard;
a broader outer-guard contract is not granted. The backend itself is
resolved only from the actual product executable's matching install or build
layout, then pinned by exact 8916 bytes, SHA and physical UID before publication
and again at EOF. It is emitted after the existing facade using the same
transactional prefix insertion. Existing edits and overlap rejection remain.

Selected header group values request the existing strict joint source parse.
The proof is reconstructed in that CompilerInstance. Only plain SDK tuple,
physical input SHA/UID/size and the existing full token/final-macro evidence
cross the LocalHeader boundary. No AST pointer crosses. Provider or tuple
differences refuse publication. Mixing dynamic groups with deferred inherited
sample-helper discovery is currently conservatively refused if the original
and strict-joint provider ledgers differ; this draft grants no discovery bypass.

## Runtime and remaining original-source gates

The unchanged backend checks caller membership and all group members active at
each real register exchange; unrelated active groups are permitted. Static32
partition requires the full active physical warp. Grid coordinates check 1D
launch dimensions at runtime. No memory-order, grid/partial-warp barrier or
synchronization capability is added. Int sum uses proven int32 representation
and defined uint32 modular arithmetic; that does not validate originally
undefined signed CUDA input domains.

The four original `__CUDA_ARCH__ >= 700` regions and runtime capability query in
warpAggregatedAtomicsCG are unresolved source-selection gates. They cannot be
dropped, globally defined or replaced by fabricated CUDA architecture values.
The binary sample's real async input and synchronized outputs still require a
separate actual-input oracle. Original 13.0 sources and workloads stay intact.

fresh native/CTest and full same-binary old/new regressions precede complete
original target conversion/O2/link/provider/resource checks. In particular,
new dormant declarations in reduce.h must pass the existing generic record
and dependent-type audit without any whole-file exception; a first rejection
is evidence to preserve and close narrowly. A plain converter zero is not
original sample acceptance. Root alone schedules every engineering/original
