# Bounded dynamic-kernel launch ABI completion

CANN9.1 CPU contrasts observed a host-stub copy length of 44 bytes for three 64-bit pointers followed by an unsigned 32-bit integer, although the compiler stored block/grid metadata through byte 47. Adding an anonymous default unsigned 32-bit parameter made the real host stub copy 48 bytes; all four original argument offsets remained 0/8/16/24, and a four-argument launch supplied zero for the fifth value. This is an observed toolchain layout mismatch. The CPU contrast alone does not establish the unique cause of the prior device 355 failure. The corrected complete original target subsequently passed one NPU execution and exact actual-input checks; see the [validation record](validation/binary-partition-cg-20261103.md).

The source completion only consumes a successful current-CI dynamic-group factory proof. Eligible kernels have a literal main-file ordinary global definition, one or more naturally aligned 64-bit data-pointer parameters followed by exactly unsigned int32, and one four-byte tail hole. The source must have at least one ordinary direct host launch; all other kernel references must be an exact already-proven occupancy argument. Redeclarations, function templates, existing defaults/parameter attributes, same-name declarations and lookup observations, function/source signature observations, symbol aliases, inline/global assembly and NTTP/pack observations refuse completion. The default target-only suffix is `, unsigned int = 0u`; original source, original launch arguments, group algorithm and workload stay intact. Source edits commit atomically after the completed occupancy proof and retain all existing whole-TU audits. No general SDK/type/body exemption is added.

This is a closed single-TU source contract for the original target. It does not guarantee transparency to external binary identity observers, cross-TU dynamic symbols, or arbitrary external ABI consumers. Other signatures retain their prior source domain without a new completion witness; internal padding patterns are not guessed from the sum of parameter sizes.

The repository regression embeds the same six real-source fixtures: one exact completion and same-name ordinary/template overload, NTTP, pack and file-scope assembly refusals. It checks real-SDK Clang host source validity and optionally native NVCC; external Clang device mode with this newer CUDA SDK may fail at cudaConfigureCall and is not an accepted source-validity proof. NTTP fixtures currently hit the earlier address-escape gate, so their results do not independently cover the declaration-template inventory leaf. Fresh and existing-output refusals require rc1, failed receipts, no new bundles and unchanged 640-mode sentinel metadata. No CCEC or device execution is performed by this test.
