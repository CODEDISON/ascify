# Original shfl_scan validation

The unchanged CUDA Samples v13.0 `shfl_scan` passed its complete owned O2 target
build and one formal execution on Ascend950DT with CANN 9.1.0. RDC, the original
algorithm and workloads, and the 120-thread rows block were retained. The fixed
build links one generated device object and zero user device archives.

The external oracle checked all four D2H outputs: 65,536 + 256 + 2,073,600 +
2,073,600 = **4,212,992 exact integer values**. Original scan and row differences
were zero; the integral checksum was 2,073,600. Device health and bound inputs
were unchanged before and after the run.

Translator SHA-256: `35ba502d4c20231e84d2f1494c1224db32f99a8c1633aa97b64e8d97d29e7eb1`.
The linked [acceptance receipt](shfl-scan-20261106.json) records the program,
source identities, actual process IDs and remote evidence SHA-256 values.

The same translator passed 307 existing software cases without expectation
changes, the supplemental legacy pair, 30 additional dynamic/ABI checks,
two literal/macro barrier cases, and the finite source/argument and UID checks.
An initial host-unit link failed because its output path was a log directory;
a link-only continuation reused its successful object and ran the first two
UID units. The failed attempt remains in the evidence.

The raw compiler tail is now checked before tooling discards extra inputs;
foreign archive/linker arguments are refused while preserving existing output.
Provider file reads use blocks while retaining complete-content hashing and
all physical identity checks. The source and helper admission conditions are
documented in the [owned target guide](../owned-device-executable.md).

This acceptance adds one historical vector sample (19/38) and one core sample
(34/75). Other original samples retain their own product evidence. It establishes
correctness for this bounded target and original workload, with no performance
or arbitrary parent-build claim. Full builds, objects and captures remain on DT.
