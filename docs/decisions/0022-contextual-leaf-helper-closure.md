# ADR 0022: Prove a contextual leaf expansion before jointly converting helpers

Status: accepted for implementation; real frontend and DT validation recorded by the release gate.

The original CUDA translation unit can legally use an NVIDIA sample helper macro in a local header when the parent has already included the helper. The previous recursive closure parsed each selected header as an independent translation unit, losing that parent state. Keeping the parent helper include did not make an independently generated child valid. This is a converter context boundary; it says nothing about target hardware support.

We use an intentionally bounded contextual path instead of manufacturing a standalone environment. The normal root discovery pass remains unpublished. The contextual proof requires actual standard preprocessing (`--default-preprocessor` or its skip-excluded synonym), and rejects `--amap`. Retaining excluded conditional blocks cannot establish C++ semantic equivalence: an inactive `__COUNTER__` can still be visited and conceal a real counter-state difference. A recognized helper use in a selected direct quoted header requests a context proof. At the original root path, the frontend parses the original source again and inventories physical inputs and include edges. A selected candidate must have exactly one direct include occurrence, one file entry, no nested quoted include, and no pragma. The include must occupy a single literal directive line. The header must end in a newline. Recursive helper expansion and target recipes are outside this path's admitted domain.

The engine substitutes the original leaf bytes at their original include position in a virtual root buffer. `#line` preserves the leaf's source filename and line numbering, then restores the parent's presumed filename and next line. It adds no forced include, assumed definition, or workload-specific rule. The second parse uses `ClangTool::mapVirtualFile` and `run`, never `runAndSave` on the input source.

Admission requires equal SHA-256 digests for the complete expanded token streams and effective final macro states. Token spellings include actual `__FILE__`, `__LINE__`, `__COUNTER__`, `__INCLUDE_LEVEL__`, and other builtin expansions; none is normalized away. Final macro definitions include function/object/builtin kind, parameter names, variadic flags, replacement token kinds/spellings/leading space, and the preprocessor's final counter. A changed active include-level expression or a changed definition in a branch without C++ output must therefore reject. Deferred builtin macros continue to expand at their use location; the regression covers a header-defined `__FILE__` macro used later in the parent.

The joint virtual translation must also commit the existing complete helper transaction. Proven token equivalence does not bypass helper declaration provenance, raw macro observations, unsupported status expressions, name capture, or target-header checks. If the helper transaction retains its original include or a participating call, contextual conversion fails. Other local headers continue through the existing closure machinery; this decision does not generalize independent conversion to arbitrary transitive state.

The published closure manifest retains the original root and header paths and SHA-256 values, original include graph, substituted header and include offset, and token/macro proof digests, including for an inline-only bundle. The root digest must match the exact saved original buffer used for parsing; rereading a concurrently changed root cannot relabel that buffer. Each observed lexical path is bound to its canonical target and rechecked, so stable SDK symlinks are permitted but retargeting is rejected. All physically observed input bytes are rechecked before publication and included in artifact isolation. Both discovery output and the joint output remain in the existing private staging transaction until all closure checks pass. A failed proof removes staging and preserves any previous root and owned bundle. The source and its vendored headers are never edited.

The real frontend regression `tests/rewrite/check_inherited_sample_helper_context.py` checks an ordinary positive, a positive with source-line and deferred builtin state, and negative cases for retained-conditional preprocessing, repeated include, active include-level token changes, final macro-only state changes, final counter changes, explicit pragma, a parent-defined `_Pragma` invoked in the leaf, nested quoted includes, and an unproven joint helper transaction. Every negative exercises both a fresh output and a retry over a previously published root and manifest. The gate compares source bytes before and after each invocation.

This establishes conversion behavior within the stated input domain. Successful conversion alone does not establish target compilation, dynamic shared-memory execution, synchronization correctness, or performance; those remain separate DT tests for the original 20 samples.
